# FL-02: Split-Tender Sale (Cash + Card + UPI)

> **Domain:** Finance, Stock & Account Integrity (Prompt 77)  
> **Personas:** `cashier`, `store_owner`  
> **Key Invariants:** `INV-1`, `INV-3`, `INV-4`, `INV-18`  
> **Callables:** `billsCreate`, `billsFinalize`, `accountEntriesList`  

---

## 1. Overview
Customer splits total bill across cash drawer and card/UPI clearing accounts. Multiple account transactions are created atomically.

## 2. Executable Steps & Request Payloads

### Step 1: Create bill with split payments
- **Callable:** `billsCreate`
- **Request Payload:**
```json
{
  "totalAmount": 100000,
  "splitPayments": [
    {
      "method": "cash",
      "amount": 40000
    },
    {
      "method": "card",
      "amount": 60000
    }
  ]
}
```

### Step 2: Finalize bill
- **Callable:** `billsFinalize`
- **Request Payload:**
```json
{
  "billId": "bill_002"
}
```

### Step 3: Verify multiple ledger entries created across both accounts
- **Callable:** `accountEntriesList`
- **Request Payload:**
```json
{
  "sourceDocumentId": "bill_002"
}
```


## 3. Invariant Assertions & Expected State
- **INV-1:** Must hold before and after each transaction in this flow.
- **INV-3:** Must hold before and after each transaction in this flow.
- **INV-4:** Must hold before and after each transaction in this flow.
- **INV-18:** Must hold before and after each transaction in this flow.
- Balance updates must be atomic and synchronized across running balance fields.

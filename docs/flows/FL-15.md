# FL-15: Day-End Physical Cash Count & Variance Adjustment

> **Domain:** Finance, Stock & Account Integrity (Prompt 77)  
> **Personas:** `cashier`, `branch_manager`  
> **Key Invariants:** `INV-15`  
> **Callables:** `cashCountsCreate`, `cashCountsGet`  

---

## 1. Overview
End of day denomination counting. Discrepancy between counted cash and system running balance generates an adjustment entry.

## 2. Executable Steps & Request Payloads

### Step 1: Submit physical cash count
- **Callable:** `cashCountsCreate`
- **Request Payload:**
```json
{
  "financialAccountId": "acc_cash_1",
  "denominations": {
    "100": 30,
    "200": 10,
    "500": 20
  },
  "notes": "Day end register tally"
}
```

### Step 2: Retrieve recorded count with variance transaction
- **Callable:** `cashCountsGet`
- **Request Payload:**
```json
{
  "countId": "cnt_001"
}
```


## 3. Invariant Assertions & Expected State
- **INV-15:** Must hold before and after each transaction in this flow.
- Balance updates must be atomic and synchronized across running balance fields.

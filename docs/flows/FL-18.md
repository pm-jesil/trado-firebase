# FL-18: Maker-Checker Document & Entry Approval Workflow

> **Domain:** Finance, Stock & Account Integrity (Prompt 77)  
> **Personas:** `employee_maker`, `manager_checker`  
> **Key Invariants:** `INV-16`, `INV-17`  
> **Callables:** `accountEntriesVerify`, `documentsDecide`  

---

## 1. Overview
High-value ledger entry or document submitted by employee routes to supervisor. Maker cannot verify or approve own entry.

## 2. Executable Steps & Request Payloads

### Step 1: Checker verifies entry
- **Callable:** `accountEntriesVerify`
- **Request Payload:**
```json
{
  "entryId": "txn_manual_1",
  "note": "Voucher supporting documentation checked"
}
```

### Step 2: Approver gives final approval
- **Callable:** `documentsDecide`
- **Request Payload:**
```json
{
  "documentType": "account_entry",
  "documentId": "txn_manual_1",
  "decision": "approve"
}
```


## 3. Invariant Assertions & Expected State
- **INV-16:** Must hold before and after each transaction in this flow.
- **INV-17:** Must hold before and after each transaction in this flow.
- Balance updates must be atomic and synchronized across running balance fields.

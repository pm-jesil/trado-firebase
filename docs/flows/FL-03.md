# FL-03: Credit Sale & Subsequent Customer Collection

> **Domain:** Finance, Stock & Account Integrity (Prompt 77)  
> **Personas:** `salesperson`, `accountant`  
> **Key Invariants:** `INV-1`, `INV-3`, `INV-4`  
> **Callables:** `billsCreate`, `billsFinalize`, `paymentsCreate`, `accountEntriesList`  

---

## 1. Overview
B2B sale on credit (paidAmount: 0). Customer outstanding receivable increases. Later, customer payment voucher settles the bill.

## 2. Executable Steps & Request Payloads

### Step 1: Create credit invoice
- **Callable:** `billsCreate`
- **Request Payload:**
```json
{
  "customerId": "cust_1",
  "paidAmount": 0,
  "totalAmount": 500000
}
```

### Step 2: Finalize credit invoice
- **Callable:** `billsFinalize`
- **Request Payload:**
```json
{
  "billId": "inv_003"
}
```

### Step 3: Record customer payment voucher
- **Callable:** `paymentsCreate`
- **Request Payload:**
```json
{
  "customerId": "cust_1",
  "amount": 500000,
  "paymentMethod": "bank_transfer",
  "referenceDocumentId": "inv_003"
}
```


## 3. Invariant Assertions & Expected State
- **INV-1:** Must hold before and after each transaction in this flow.
- **INV-3:** Must hold before and after each transaction in this flow.
- **INV-4:** Must hold before and after each transaction in this flow.
- Balance updates must be atomic and synchronized across running balance fields.

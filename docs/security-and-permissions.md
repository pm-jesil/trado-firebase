# Trado Security, Rules & Permissions Model

> **Canonical Companion**: For the complete role hierarchy, four-layer resolution engine, and privilege matrix, see [Permissions & Roles](permissions-and-roles.md).

This document specifies the complete security architecture for Trado, including Cloud Firestore Security Rules, Cloud Storage Security Rules, the 4-layer dynamic RBAC permission evaluation engine, and the 105-code canonical permission catalog.

---

## 1. Security Architecture Principles

1. **Defense-in-Depth**:
   - Layer 1: Client HTTPS Request verification (Firebase Auth tokens, custom claims, App Check readiness).
   - Layer 2: Cloud Functions Gen 2 request context resolver (`contextResolver.ts`) enforcing tenant boundary, branch assignment, and permission checks.
   - Layer 3: Serverless database isolation (Firestore Security Rules & Cloud Storage Rules denying unauthorized reads and non-admin direct writes).

2. **Zero-Trust Client Writes**:
   - All state mutations (billing, stock adjustments, outflows, payments, task updates, user provisioning) MUST execute through HTTPS Callables.
   - Direct client writes to sensitive business collections (`organizations`, `bills`, `outflows`, `stockBalances`, `stockMovements`, `payments`, `roles`, `memberships`) are strictly set to `allow write: if false;` in `firestore.rules`.
   - Only validated Cloud Functions using the Firebase Admin SDK (which bypasses client rules) can commit mutations.

3. **Multi-Tenant Read Isolation**:
   - Read operations permitted to client SDKs strictly verify that the requesting user's custom claim `token.primaryOrganizationId` matches the document's `organizationId`.
   - Cross-tenant queries return zero records or throw `permission-denied`.

## 2. Canonical RBAC Permission Catalog (105 Codes)

The catalog is defined canonically in `functions/src/constants/permissions.ts`. Permissions follow a hierarchical `domain:action` or `domain:subdomain:action` pattern.

### Platform Super Admin
- `*`: Root platform wildcard.
- `platform:*`: All platform-level administrative actions.
- `platform:dashboard`: Access cross-tenant platform health overview.
- `platform:finance:view`: View platform-wide subscription financial metrics.
- `platform:finance:manage`: Manage platform pricing and rate cards.
- `platform:tenants:view`: List and inspect tenant organizations.
- `platform:tenants:manage`: Suspend or provision tenant organizations.
- `platform:subscriptions:view`: View active tenant subscription tiers.
- `platform:subscriptions:manage`: Manage subscription plan definitions.
- `platform:users:view`: View global registered user accounts.
- `platform:users:manage`: Administrative user resets or deactivations.
- `platform:audit:view`: Inspect global security audit logs.

### Organization Management
- `org:view`: View tenant profile, metadata, and settings.
- `org:update`: Update organization business profile and contact information.
- `org:settings`: Configure tax regimes, decimal settings, currency preferences.
- `org:create`: Self-service tenant creation (or onboarding).
- `org:modules`: Toggle optional business modules within the tenant.
- `org:delete`: Deactivate or request deletion of organization account.

### Branch Management
- `branch:view`: View operating branch details and list branches.
- `branch:create`: Provision a new operating branch within subscription capacity.
- `branch:update`: Update branch address, contact details, operating hours.
- `branch:deactivate`: Deactivate a physical branch location.
- `branch:manage`: Manage all branch configurations and code locks.
- `branch:assign`: Assign staff memberships to operating branches.

### Staff, Employees & Roles
- `employee:view`: View employee list and profile metadata.
- `employee:create`: Invite or create new employee membership.
- `employee:update`: Update employee details, department, or job role.
- `employee:delete`: Remove employee from organization.
- `employee:suspend`: Suspend employee active status.
- `employee:reset_password`: Trigger employee password reset flow.
- `employee:permission_update`: Configure membership-specific permission overrides.
- `role:view`: View roles and assigned capabilities.
- `role:create`: Create custom tenant roles.
- `role:update`: Edit role capability lists.
- `role:delete`: Delete custom tenant roles.
- `role:assign`: Assign roles to staff members.
- `department:manage`: Create and manage company departments.
- `job_role:manage`: Create and manage functional job roles.
- `team:manage`: Organize staff into functional operational teams.
- `audit:view`: View tenant-level security audit trail.

### Billing & POS
- `bill:view`: View sales bills and POS tickets.
- `bill:view_all`: View bills generated by all staff across the organization.
- `bill:create`: Create sales invoices, POS tickets, and quotations.
- `bill:update`: Edit draft bills or quotations.
- `bill:print`: Reprint customer invoice documents.
- `bill:discount`: Apply line-item or bill-level discounts.
- `bill:void`: Void active or draft bills with compensating inventory restoration.
- `bill:return`: Process customer sales returns.

### Sales & POS Mode
- `sale:view`: View quick sales registers.
- `sale:create`: Process quick POS counter checkout.

### Products, Catalog & Inventory
- `product:view`: View product catalog items, prices, and stock indicators.
- `product:create`: Add new products to tenant catalog.
- `product:update`: Update product specifications, prices, tax codes.
- `product:delete`: Deactivate products from catalog.
- `category:view`: View catalog categories.
- `category:manage`: Create, edit, and deactivate categories.
- `unit:view`: View measurement units.
- `unit:manage`: Create and manage unit codes and conversion rates.
- `inventory:view`: View physical branch stock balances.
- `inventory:adjust`: Perform manual inventory count adjustments.
- `inventory:manage`: Complete stock configuration and threshold management.

### Stock Movements
- `stock:view`: View audit trail of physical inventory movements.
- `stock:adjust`: Record damaged, expired, or shrinkage adjustments.
- `stock:transfer`: Execute inter-branch stock transfers.

### Outflows (Purchases & Expenses)
- `outflow:view`: View purchase invoices and expense vouchers.
- `outflow:create`: Draft purchase or expense vouchers.
- `outflow:approve`: Confirm and finalize vendor purchases.
- `outflow:void`: Void recorded expenses.
- `purchase:view`: View purchase orders.
- `purchase:create`: Log supplier purchase orders.
- `purchase:approve`: Approve bulk purchase orders.
- `expense:view`: View operational expenses.
- `expense:create`: Log petty cash or branch expenses.
- `expense:approve`: Approve expense reimbursements.

### Customers & Vendors
- `customer:view`: View customer directory and party ledger balances.
- `customer:create`: Onboard new customers.
- `customer:update`: Update customer contact and credit terms.
- `customer:delete`: Deactivate customer profile.
- `vendor:view`: View supplier list and payable ledgers.
- `vendor:create`: Onboard new suppliers and vendors.
- `vendor:update`: Update vendor payment terms and details.
- `vendor:delete`: Deactivate vendor profile.

### Payments Ledger
- `payment:view`: View inward and outward payment receipts.
- `payment:create`: Record customer payment received or vendor payment made.
- `payment:void`: Void erroneous payment entries with ledger balance rollback.

### Dispatch & Deliveries
- `delivery:view`: View dispatch queue and delivery statuses.
- `delivery:create`: Create delivery order linked to a sales invoice.
- `delivery:update`: Update delivery milestone (dispatched, delivered, failed).
- `delivery:assign`: Assign delivery orders to riders or external couriers.

### Returns Management
- `return:view`: View sales and purchase return records.
- `return:create`: Initiate return request.
- `return:approve`: Authorize refund and inventory restock.

### Reports & Business Intelligence
- `report:view`: View basic operational reports (daily sales, item velocity).
- `report:profit`: View Profit & Loss reports with Cost of Goods Sold (COGS).
- `report:export`: Export data to CSV/Excel formats.

### Task Management
- `task:view`: View assigned tasks.
- `task:create`: Create task for self.
- `task:update`: Update task notes and progress status.
- `task:delete`: Delete task records.
- `task:assign`: Assign tasks to other staff members across the organization.

### Live Location Tracking
- `location:ping`: Post periodic foreground/background location coordinates.
- `location:view_own`: View caller's own route history.
- `location:view_all`: Dispatch/manager capability to view all field staff live positions.
- `location:manage`: Configure employee location consent and tracking settings.

### Notifications
- `notification:view`: View and manage in-app notifications.

## 3. Firestore Security Rules Structure (`firestore.rules`)

1. **Helper Functions**:
   - `isAuthenticated()`: Checks `request.auth != null`.
   - `isSuperAdmin()`: Checks `request.auth.token.isSuperAdmin == true`.
   - `isMemberOf(orgId)`: Checks `request.auth.token.primaryOrganizationId == orgId`.
   - `isBranchScoped(orgId, branchId)`: Verifies caller's active branch assignment.

2. **Collection Matrix**:
   - `users/{uid}`: Read allowed only by self (`request.auth.uid == uid`) or Super Admin. Direct write denied.
   - `users/{uid}/devices/{deviceId}`: Read and write allowed by self to register FCM device tokens.
   - `organizations/{orgId}`: Read allowed by tenant members. Write denied.
   - `organizations/{orgId}/branches/{branchId}`: Read allowed by tenant members. Write denied.
   - `memberships/{membershipId}`: Read allowed by tenant members. Write denied.
   - `products`, `categories`, `units`: Read allowed by tenant members. Write denied.
   - `bills`, `outflows`, `payments`, `deliveries`, `returns`: Read allowed by tenant members matching `organizationId`. Write denied.
   - `stockBalances`: Read allowed by tenant members matching `organizationId`. Write denied.
   - `branchCodeLocks`, `barcodeLocks`: Write and client reads denied (Functions internal only).
   - `tasks`: Read allowed by tenant members. Write denied.
   - `latestLocations`, `locationPings`: Read allowed only with manager permission or self. Write denied.
   - `notifications`: Read allowed by recipient user (`resource.data.userId == request.auth.uid`). Write denied.
   - `dailySummaries`, `monthlySummaries`: Read allowed by tenant members. Write denied.
   - `organizationUsageDaily`, `branchUsageDaily`, `platformUsageSnapshots`: Super Admin read only. Write denied.

## 4. Cloud Storage Security Rules Structure (`storage.rules`)

- Storage bucket paths are partitioned by tenant: `organizations/{organizationId}/...`
- Uploads and reads require `request.auth.token.primaryOrganizationId == organizationId`.
- Maximum file sizes and MIME types are strictly validated (e.g. max 5MB for images/logos, max 10MB for documents).
